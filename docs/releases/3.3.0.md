# Compasso 3.3.0: upgrade notes

Read this whole file before changing anything. It says what changed, what is new, and what to do in each project. 3.3.0 changes how stories are tested and adds no configuration, label or tracker command.

## What changed

- **Each acceptance line is tested once,** at the cheapest level that can observe it. The planner chooses a story's `tests` by line: `unit` for logic, rules, edge and abuse cases; `e2e` only for a line that needs the real boundary (a flow across screens, the public API, the CLI, another service). A story's tests may be `unit`, `e2e` or both; before, `unit` was always required. The tester never tests one line at both levels, unless the e2e test checks the wiring itself.
- **A finished feature gets e2e tests only for what its stories' tests left out.** The tester reads the stories' e2e tests first. When they cover every acceptance line of the feature it writes none and there is no e2e merge request; the whole suite and e2e still run, and a failure still becomes a bug under the feature.
- **Verify runs e2e last,** and only when every other command passed: a failing attempt no longer pays for the slowest suite. The output says `SKIP  [e2e] ... - an earlier command failed`.
- **No local coverage in `stage: mvp`.** `coverage.sh` runs nothing there; the merge request's Coverage line says "not measured in the MVP". The `mvp` pipeline already left coverage out (3.2.0). In `production` nothing changes.
- **No tests of prose.** The tester refuses tests that pin the wording of docstrings, comments or documentation, and the reviewer files a wrong comment as a finding to fix in its text.

## What is new

- `verify.sh --e2e`: runs the e2e command without a story. The sprint flow uses it to verify a finished feature and for the regression at sprint close (before, those runs did not include e2e unless the agent ran it by hand).
- **Time in checks.** `verify.sh` and `coverage.sh` record each command's seconds: `verify.json` has `seconds` per command, and the story's metrics file (`.compasso/metrics/<iid>.json`) has `verify_seconds` per command label. The sprint report adds `quality.verify_minutes` and a "Time running checks" tile. Stories built before the upgrade have no times: the tile says "not recorded".

## What to do in each project

1. **Update the plugin and restart.** Run `claude plugin marketplace update compasso` and `claude plugin update compasso@compasso`, then restart the session. Run `/compasso:status`: if it warns that a newer Compasso is installed than the one running, restart again, until it no longer warns.
2. **Nothing on the tracker, the pipeline or the configuration.** 3.3.0 adds no label, no configuration key and no pipeline job; do not run `ci.sh` for this release.
3. **The current plan stays valid.** Stories already planned with `tests: [unit, e2e]` keep them: do not re-plan them. The new rule applies to stories planned from now on (`/compasso:plan`, `/compasso:feature`).
4. **A feature already in `compasso::verifying`** whose e2e merge request is open: let it finish as it is.
5. **Coming from a version before 3.2.0:** first read [3.2.0.md](3.2.0.md) and follow its "What to do in each project" section.

## Check

- `/compasso:status` shows no warning about a newer Compasso.
- `bash ${CLAUDE_PLUGIN_ROOT}/bin/plan-check.sh --repo .` passes on the current plan.
- After the next story is built, its `.compasso/runs/<iid>/verify.json` has `seconds` on every command, and in `stage: mvp` its merge request's Coverage line says "not measured in the MVP".
